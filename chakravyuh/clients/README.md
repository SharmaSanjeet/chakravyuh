# Chakravyuh - Agentless shippers

Shipping (shipper) scripts with **no heavy software installation**. They run via cron
(POSIX) or Scheduled Task (Windows), read the web server's access log, keep **only the
lines that match the lure prefix**, and send them HMAC-signed to the Chakravyuh server.

- `chakravyuh-ship.sh` — POSIX `sh`. Needs only `curl`, `openssl` and `awk`.
- `chakravyuh-ship.ps1` — PowerShell 5+ (Windows), no external dependencies.

Both are **idempotent** (a log byte-offset prevents resending; the server also
deduplicates) and **never** modify or delete the source log.

## Privacy

The script sends **only** the lines whose content includes
`CHAKRAVYUH_BASE_PATH` (the lure prefix). Real user traffic never leaves the host.
That is why `CHAKRAVYUH_BASE_PATH` is mandatory: without a prefix the whole log
would be sent, and the script refuses to run.

## Environment variables

| Variable           | Req. | Description                                                        |
|--------------------|:----:|--------------------------------------------------------------------|
| `CHAKRAVYUH_SERVER`    |  yes  | Base URL of the Chakravyuh server (e.g. `https://chakravyuh.example.com`). |
| `CHAKRAVYUH_KEY_ID`    |  yes  | Sensor key identifier.                                             |
| `CHAKRAVYUH_SECRET`    |  yes  | Sensor HMAC secret (keep it private).                              |
| `CHAKRAVYUH_LOG`       |  yes  | Access log path (e.g. `/var/log/nginx/access.log`).                |
| `CHAKRAVYUH_BASE_PATH` |  yes  | Lure prefix (e.g. `/lure`).                                        |
| `CHAKRAVYUH_FORMAT`    |  no   | `nginx` \| `apache` \| `caddy` \| `json` \| `raw`. Default `nginx`. |
| `CHAKRAVYUH_STATE`     |  no   | Offset file. Default: next to the script, unique per log path.     |
| `CHAKRAVYUH_DRY_RUN`   |  no   | `1` = print what would be sent and exit (touches neither the network nor the offset). |

## Behavior

1. **Offset + rotation**: stores the byte offset read. If the current size of the
   log is smaller than the stored offset (rotation/truncation), it resets to `0`. Only
   the new lines from the offset onward are read. The last line without `\n` (possibly
   mid-write) is left pending for the next run.
2. **Filtering** by `CHAKRAVYUH_BASE_PATH` (see *Privacy*).
3. Signed **`GET /control`**. The **server signature is verified**
   (`X-Chakravyuh-Server-Signature`) before trusting the response; on mismatch, it
   aborts without sending (anti-MITM protection).
4. If `enabled=false`: **nothing is sent and the offset is NOT advanced** (design
   decision), so no lure lines are lost when the sensor is re-enabled. Meanwhile the
   script re-reads those same lines on every run, but they **never leave the
   host** until the sensor is re-enabled.
5. Signed **`POST /ingest/logs`**, in batches of up to **20,000 lines** per request.
   The offset only advances after **all** batches succeed.
6. Lines that do not match the prefix (real traffic) do advance the offset to avoid
   rescanning them, but they are never sent.

### Signature (identical to `chakravyuh/security.py`)

```
ts        = <unix epoch with decimals, as a string>
message   = ts + "." + <exact body>          # empty body for GET /control
signature = "sha256=" + HMAC_SHA256_hex(CHAKRAVYUH_SECRET, message)
```

Headers: `X-Chakravyuh-Key-Id`, `X-Chakravyuh-Timestamp`, `X-Chakravyuh-Signature`.

## Example: cron (POSIX, every 5 minutes)

Prefer storing the secrets in an environment file with `600` permissions instead of
leaving them in the crontab:

```sh
# /opt/chakravyuh/ship.env   (chmod 600)
export CHAKRAVYUH_SERVER=https://chakravyuh.example.com
export CHAKRAVYUH_KEY_ID=ck_xxxxxxxxxxxxxxxx
export CHAKRAVYUH_SECRET=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
export CHAKRAVYUH_LOG=/var/log/nginx/access.log
export CHAKRAVYUH_BASE_PATH=/lure
export CHAKRAVYUH_FORMAT=nginx
```

```cron
# crontab -e
*/5 * * * * . /opt/chakravyuh/ship.env && /opt/chakravyuh/chakravyuh-ship.sh >> /var/log/chakravyuh-ship.log 2>&1
```

Or all in one line (as generated by the provisioning wizard):

```cron
*/5 * * * * CHAKRAVYUH_SERVER=https://chakravyuh.example.com CHAKRAVYUH_KEY_ID=ck_... CHAKRAVYUH_SECRET=... CHAKRAVYUH_LOG=/var/log/nginx/access.log CHAKRAVYUH_BASE_PATH=/lure /opt/chakravyuh/chakravyuh-ship.sh >/dev/null 2>&1
```

## Example: Scheduled Task (Windows, every 5 minutes)

```powershell
# Run once as administrator to register the task.
$envBlock = @'
$env:CHAKRAVYUH_SERVER   = "https://chakravyuh.example.com"
$env:CHAKRAVYUH_KEY_ID   = "ck_xxxxxxxxxxxxxxxx"
$env:CHAKRAVYUH_SECRET   = "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
$env:CHAKRAVYUH_LOG      = "C:\logs\access.log"
$env:CHAKRAVYUH_BASE_PATH= "/lure"
$env:CHAKRAVYUH_FORMAT   = "nginx"
& "C:\chakravyuh\chakravyuh-ship.ps1"
'@
Set-Content -Path C:\chakravyuh\run-ship.ps1 -Value $envBlock -Encoding UTF8

$action  = New-ScheduledTaskAction -Execute "powershell.exe" `
           -Argument '-NoProfile -ExecutionPolicy Bypass -File C:\chakravyuh\run-ship.ps1'
$trigger = New-ScheduledTaskTrigger -Once -At (Get-Date) `
           -RepetitionInterval (New-TimeSpan -Minutes 5)
Register-ScheduledTask -TaskName "Chakravyuh Shipper" -Action $action -Trigger $trigger `
           -RunLevel Highest -Description "Agentless shipping of lure logs to Chakravyuh"
```

> Protect `run-ship.ps1` with a restrictive ACL: it contains the secret.

## Dry-run

Always do a dry run before scheduling the task:

```sh
CHAKRAVYUH_SERVER=https://chakravyuh.example.com CHAKRAVYUH_KEY_ID=ck_... CHAKRAVYUH_SECRET=... \
CHAKRAVYUH_LOG=/var/log/nginx/access.log CHAKRAVYUH_BASE_PATH=/lure CHAKRAVYUH_DRY_RUN=1 \
  sh /opt/chakravyuh/chakravyuh-ship.sh
```

It prints the exact JSON body/bodies and the signed headers that would be sent,
**without** contacting the server and **without** advancing the offset. Verify that:

- only lure lines appear (none from real traffic),
- the format (`CHAKRAVYUH_FORMAT`) matches your web server.

## Signature parity verification (done)

The HMAC signature of the scripts was verified to match `chakravyuh.security.sign`
**byte for byte**:

```sh
# POSIX / openssl  (what sign_file does in chakravyuh-ship.sh)
SECRET=...; TS=1760000000.123; BODY='{"format":"nginx",...}'
{ printf '%s.' "$TS"; printf '%s' "$BODY"; } | openssl dgst -sha256 -hmac "$SECRET" | awk '{print $NF}'

# Python reference
python -c "from chakravyuh import security; print(security.sign('$SECRET','$TS', b'...'))"
```

Result: identical for a full body and for an empty body (GET `/control`), even with
secrets that start with `-` (e.g. from `token_urlsafe`). The PowerShell version
(`HMACSHA256` over `UTF8(ts + "." + body)`) produces the same hash.
In addition, the JSON body generated by both scripts was parsed with
`chakravyuh.logparse.parse` and the verification of `X-Chakravyuh-Server-Signature` was tested
against a response signed with `chakravyuh.security.sign` (including a tampering test that
is correctly rejected).

## Security note

On POSIX the secret is passed to `openssl dgst -hmac` as an argument; it is briefly
visible in the host's own process list. It is the same secret that already lives in
the cron environment; keep the host and the environment file locked down with
restrictive permissions.
